## Bugs Found and Fixed

### Bug 1: Company dropdown shows [Object Object]
- **Symptom**: Company dropdown on Windows showed `[Object Object]` instead of names
- **Root cause**: Real Tally returns XML elements with attributes, which xml2js parses as `{ _: "text", $: { attr: "val" } }` instead of plain strings. Mock server returned simple XML so this never surfaced.
- **Fix**: Added `_text()` helper in `tally.service.js` that handles both plain strings and xml2js attribute objects. Applied to `listCompanies()`, `listStockGroups()`, and `_parseStockItem()`.

### Bug 2: Stock groups not loading
- **Symptom**: No stock groups displayed after selecting company
- **Root cause**: Same xml2js attribute object issue as Bug 1
- **Fix**: Same `_text()` helper applied to `listStockGroups()` parsing

### Bug 3: Config save fails on Windows build (ENOENT)
- **Symptom**: `Failed to save ENOENT: no such file or directory, open 'C:\Users\...\app.asar\c...\agent.config.json'`
- **Root cause**: In packaged Electron builds, `__dirname` points inside `app.asar` which is read-only. Works in dev mode (`npm start`) but fails in production.
- **Fix**: Added `getConfigPath()` helper in `index.js` — in dev mode uses project's `config/` dir, in packaged builds copies bundled config to `AppData/bytephase-agent/config/` on first run and uses that writable copy.

### Bug 4: Test Connection ignores host/port changes
- **Symptom**: Changed Tally Host to `192.168.1.9` but Test Connection still tried `localhost`
- **Root cause**: `testTallyConnection()` in renderer called `test-tally-connection` IPC without first saving the new host/port to the backend
- **Fix**: Added `save-tally-config` call with current host/port values before testing connection

### Bug 5: Delta sync always returns all items
- **Symptom**: Delta sync returned 196 items every time, even without modifications
- **Root cause**: Three issues:
  1. TDL filter used `$$LASTMODIFIEDDATE` (function call) instead of `$LASTMODIFIEDDATE` (field access) — returned empty collection
  2. After fixing to `$LASTMODIFIEDDATE`, date-based filtering (`>=` today) always matched all items modified today
  3. Tally's `LASTMODIFIEDDATE` is date-only (no timestamp), making same-day delta tracking impossible
- **Fix**: Switched entirely from date-based to `ALTERID`-based delta sync. ALTERID is an incrementing number in Tally that increases with every modification, giving precise change tracking.
