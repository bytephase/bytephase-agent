## Bugs Found and Fixed

### Bug 1: Rate parsing returns 0 for all items
- **Symptom**: All stock items showed `rate: 0` in sync output
- **Root cause**: `_parseRate()` regex `[₹$,\/\w\s]+$` — `\w` matches digits, so `350/Nos` got stripped to empty string
- **Fix**: Simplified to `str.replace(/[₹$\s,]/g, '')` then extract number with `/-?[\d.]+/`
- **Verified**: 350/Nos → 350, ₹ 1,200.50/Nos → 1200.5, ₹ 150.00 → 150

### Bug 2: Tray popup Sync Now button always disabled
- **Symptom**: Button appeared greyed out and unclickable
- **Root cause**: Condition `!data.registered || !data.tallyStatus.connected` — agent not registered with cloud API key during local testing
- **Fix**: Removed `!data.registered` check — Tally sync is a local operation, doesn't require cloud registration

### Bug 3: Agent-connected notification 404 (pre-existing since January)
- **Symptom**: `[ERROR] Agent connected notification FAILED: Request failed with status code 404` when opening directory scan from live CRM
- **Root cause**: Two issues:
  1. URL was `/api/directory-scans/{jobId}/progress` but backend route is `/api/agent/directory-scans/{jobId}/progress` (missing `/agent/`)
  2. Missing `X-Tenant` header required by backend `InitializeTenancyByRequestData` middleware
  3. `shopId` was not being passed from scan UI to IPC handler
- **Fix**: Corrected URL, added `X-Tenant` header, passed `shopId` through IPC
- **Impact**: CRM should now immediately show "Agent Connected" status when scan window opens

### Issue 4: Stock groups failed to load (mock server only)
- **Symptom**: "Failed to load stock groups" in UI
- **Root cause**: Mock server returned unescaped `&` in "Tools & Equipment" group name, causing xml2js parse error
- **Fix**: Added `escapeXml()` helper to mock server. Not a production bug (Tally returns properly escaped XML).

## Connection Flow Research Findings

### Only directory scan deep link is fully working
Researched all 4 codebases and mapped the complete data flow:
- **Frontend** (`smart-center-frontend`): Angular app at `*.bytephase.com`. Data validation component triggers deep link, polls progress every 2s, displays results in DevExtreme FileManager.
- **Backend** (`smart-center-backend`): Laravel at `*.api.bytephase.com`. Only 2 agent endpoints exist: scan progress (Redis) and scan results (chunked → S3). Token generation via HMAC-SHA256.
- **Agent** (`bytephase-agent`): Electron desktop app. Handles deep link, validates token, scans directory, uploads chunks.
- **Partner** (`partner.bytephase.com`): NOT BUILT YET.

### What's NOT working and why
| Feature | Blocker |
|---------|---------|
| Quick Setup (paste API key) | `POST /api/agent/verify-key` not built on backend |
| Advanced Setup | `POST /api/agent/poll` not built on backend |
| Deep Link Connect (CRM) | `POST /api/agent/verify-key` not built on backend |
| Deep Link Connect (Partner) | Partner platform not built at all |
| Tally Sync Upload | `POST /api/partner/inventory/sync` not built on backend |

### Current API key situation
- Single shared key per environment in backend `.env` (`AGENT_API_KEY`)
- No per-shop agent keys, no `agents` table in DB, no key management UI in CRM
- Agent callbacks (scan results/progress) have no authentication — backend doesn't validate the API key header (MVP)

Full details: `docs/AGENT-CONNECTION-FLOWS.md`
